## 2. 공통 정의

- **선회율**: 평가 시각(scan 끝)의 정답 속도 방향이 앞뒤 scan 사이에 바뀐 각을 시간으로 나눈 값. `ω_k = wrap(ψ_{k+1} − ψ_{k−1}) / (2T)`, 양 끝에서는 한쪽 차분. 정답에 없는 scan은 건너뛴다.
- **선회 구간**: |ω| ≥ 1.0°/s인 표적-scan. 그 밖은 직선 구간. (250 kt에서 1°/s는 가로 가속도 약 2.2 m/s²)
- **ID switch 원인 분류**(위에서부터 먼저 해당하는 것 하나):
  1. `truth_gap`: 두 배정 사이에 표적이 정답에서 빠진 scan이 있음(1단계와 같음).
  2. `near_other`: 새 항적이 배정된 scan에 3 km 안에 다른 정답 표적이 있음(1단계와 같음).
  3. 나머지("표적이 있는데 잃음")를 다시 나눈다. 기준 scan은 옛 항적이 마지막으로 배정된 scan k_last, 창은 [k_last − 3, k_last + 2].
     - `turn`: 창 안 max |ω| ≥ 1.0°/s
     - `misses`: 창 안에서 그 표적의 탐지 누락이 2회 이상
     - `near_radar`: k_last에서 레이더까지 거리 < 5 km
     - `speed_change`: 창 안 max |d(속력)/dt| ≥ 1.0 m/s²
     - `unexplained`: 위 어느 것도 아님
  - 표에는 분류와 상관없이 네 값(선회율, 누락 수, 최근접 다른 표적 거리, 레이더 거리)을 모두 적는다. 겹치는 원인(선회이면서 누락)은 따로 센다.
  - **기저율**: 평가 구간의 모든 배정된 표적-scan에 같은 창을 씌웠을 때 max |ω| ≥ 1.0°/s인 비율. 잃은 항적의 선회 비율은 이 기저율과 비교한다.
- **짝 비교**: 같은 seed는 같은 탐지점을 뜻한다. 방법 A와 B의 차이는 seed별 차의 평균과 95% t-구간으로 적는다.
- **seed**: 평가 20261106–20261125(1단계와 같음). 조정 20271106부터(1단계 조정과 같은 +10000 규칙).

## 3. 질문, 지표, 예측, 판정 규칙

### Q1. 잃은 13.3회는 선회 때문인가

- 지표: "표적이 있는데 잃음" ID switch 가운데 `turn` 비율(20개 seed 합산)과 기저율, 나머지 원인별 비율.
- 판정: `turn` 비율 ≥ 50%이고 기저율의 2배 이상이면 "선회가 주원인". 비율 < 30%이면 "선회가 주원인 아님". 그 사이는 "부분적".
- 예측(Claude): `turn` 65%(50–80%), 기저율 15–25%, `misses`가 둘째로 많고 10–20%, `unexplained` 10% 미만.

### Q2. IMM(등속 + coordinated turn)이 그 실패를 줄이는가

- 구현: 모형 2개(등속 NCV, 선회율을 상태로 둔 coordinated turn EKF), 공통 상태 [x, y, vx, vy, ω]. 모형 전이는 연속시간 Markov(평균 체류 시간 τ_cv, τ_ct)에서 실제 Δt로 계산. Gating과 GNN 비용은 모형 혼합 예측의 평균·공분산으로 계산. 항적 시작·확정·삭제 규칙, gate 확률, 측정 잡음은 EKF와 같게 둔다.
- 고정값(조정하지 않음): ω 사전 표준편차 3°/s, 등속 모형이 혼합에 내놓는 ω 분산 (3°/s)², 초기 모형 확률은 정상 분포.
- 조정 격자(조정 구간 10:00–10:15 UTC에서만, seed 10개): q_cv {1, 4, 9, 25} × q_ct {9, 25} × ω 과정 잡음 {0.1, 0.3}°/s/√s × τ_cv {100, 300} s × τ_ct {20, 40} s = 64개.
- 선택 규칙: 조정 구간에서 평균 GOSPA가 EKF(q = 25)보다 크지 않은 조합 중 평균 ID switch가 가장 적은 것. 차이가 0.2회 미만이면 GOSPA가 낮은 쪽. 조건을 만족하는 조합이 없으면 GOSPA가 가장 낮은 조합을 쓰고 그 사실을 적는다.
- 정답을 아는 시험(단위 test, 실제 데이터 평가보다 먼저 통과해야 함):
  - 직선 → 3°/s 선회 → 직선 합성 궤적: 선회 중 선회 모형 확률의 평균 > 0.5, 직선 구간(선회 종료 10 scan 뒤부터) 평균 < 0.5, 추정 선회율의 부호와 크기(±1°/s 안).
  - 같은 궤적에서 선회 구간 위치 RMSE가 등속 EKF(q = 25)보다 작을 것.
  - 직선 합성 궤적: IMM 위치 RMSE ≤ 등속 EKF(q = 25) × 1.05.
  - IMM 모형과 같은 방식으로 만든 합성 정답(모형 전환 포함)에서 4차원 평균 NEES가 [3, 5.5] 안. IMM은 가우시안 혼합을 하나로 근사하므로 χ² 구간이 아니라 이 느슨한 구간을 쓴다.
- 평가(평가 구간, 20개 seed, EKF와 짝 비교): 원인별 ID switch, 항적 끊김, 위치 RMSE(전체·직선·선회), 놓친 표적, 가짜 항적, GOSPA 분해, 실제 정답 NEES, run당 실행 시간.
- 판정: "표적이 있는데 잃음" 횟수의 짝 차이(IMM − EKF) 95% 구간이 전부 0 아래면 "줄인다". 0을 포함하면 "차이를 확인하지 못함". 전부 0 위면 "늘린다". 직선 구간 RMSE 비(IMM/EKF)의 95% 구간 상한이 1.02 이하면 "직선 정확도를 해치지 않음".
- 예측(Claude): 잃음 13.3 → 7 이하(−45% 이상), 전체 ID switch 24.9 → 17–20, 선회 구간 RMSE −20%, 직선 구간 RMSE −5 ~ −10%, 실제 정답 평균 NEES 3–5, 실행 시간 EKF의 3–6배. `truth_gap`과 `near_other`는 거의 그대로.

### Q3. 독립 구현과 같은 답을 내는가

- 대상: Stone Soup 1.9.1(MIT). 프로젝트 venv에만 설치. 30분 안에 설치가 안 되면 filter 단계만 다른 구현으로 대조하고 범위를 적는다.
- 입력: 같은 탐지점(시각은 Stone Soup의 datetime 해상도에 맞춰 양쪽 모두 1 µs로 반올림), 같은 q, R, 초기 공분산, gate.
- (a) filter 단계: 표적 1개, Pd 1, 클러터 0. 갱신마다 상태와 공분산 비교. "일치" 기준: 위치 차 ≤ 1 cm, 속도 차 ≤ 1 mm/s, 공분산 상대 차 ≤ 1e-6.
- (b) 추적기 단계: 평가 구간 30분, 기준 조건, seed 20261106–20261108(3개). Stone Soup의 예측기·갱신기·Mahalanobis 가설기·GNN 2차원 배정을 쓰고, 항적 관리(확정 항적 먼저 연관, 3/4 확정, 5회 누락 삭제, 항적 시작)는 같은 규칙으로 맞춘다. scan별 확정 항적 위치와 지표(RMSE, ID switch, 놓침, 가짜, GOSPA)를 비교한다.
  - "같은 답" 기준: 확정 항적-scan의 99.9% 이상에서 위치 차 ≤ 1 cm이고 ID switch 수가 같음.
  - 다르면 처음 갈라진 scan을 찾아 원인을 연관 비용, gating, 항적 관리, 시각 처리 중 어디인지 적는다.
  - 가능하면 Stone Soup의 기본 구성(자체 시작기·삭제기)으로도 한 번 돌려 지표 차이를 적는다(판정 대상 아님).
- 예측(Claude): (a) 일치. (b) Stone Soup 가설기의 비용은 Mahalanobis 거리이고 이 프로젝트는 d² + ln|S|라서 일부 연관이 달라져 "같은 답" 기준은 못 맞출 것. 비용을 맞추면 기준을 맞출 것. 지표 차이는 RMSE 1 m 이내, ID switch ±2회 이내.

  - 디스크 여유가 15 GiB 아래로 내려가면 다른 날 원본을 받지 않는다.
  - 평가 구간 결과를 본 뒤 매개변수·분류 기준·판정 규칙을 바꾸지 않는다. 바꿔야 하면 바꾸기 전 결과를 남기고 "사전 등록과 다르게 된 점"에 적는다.
