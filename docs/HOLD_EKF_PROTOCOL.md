# Radar Track Lab: 출력 예측을 뺀 EKF 실험 프로토콜 (반대 순서)

작성: 2026-11-20, 새 변형을 구현하거나 실행하기 전. 이 파일을 커밋한 뒤에 코드를 쓰고 실행한다.
범위는 앞 단계와 같다: 민간 항공기만, 식별자 저장 안 함, 군용·LADD·PIA 제외. 기존 결과 파일(`results/data/`, `results/RESULTS.md`, `results/audit/`의 기존 파일 전부, `results/audit/predict_baseline/` 포함)과 데모 자료는 고치지 않는다. 새 산출물은 `results/audit/hold_ekf/`에 둔다.

## 1. 질문

앞 실험(`docs/PREDICT_BASELINE_PROTOCOL.md`, `results/audit/predict_baseline/summary.md`)은 "기준선 → 출력 예측 추가 → EKF" 순서에서 첫 단계가 전체 차이의 59.9%라는 값을 냈고, 이 값이 순서에 따라 달라질 수 있다고 적었다.

- H1. 반대 순서 "기준선 → (EKF의 필터와 연관, 출력은 마지막 갱신 위치 유지) → EKF"에서 출력 예측 단계의 몫은 얼마인가?
- H2. 두 순서의 몫은 비슷한가, 다른가?
- H3. 출력 예측을 뺀 EKF에서 ID switch, 끊김, 놓친 표적은 어떻게 되는가?

## 2. 이미 본 결과

- 세 방법 공통 표본(16,768개/run)의 scan-end RMSE: 기준선 527.3 m, 기준선 + 출력 예측 315.9 m, EKF 174.1 m. 첫 단계 −211.46 m, 둘째 단계 −141.80 m.
- update-time RMSE: 기준선 172.8 m, EKF 125.8 m.
- 기준선의 끊김과 놓친 표적은 출력만 바꿔도 크게 줄었다(414 → 123회, 4.02 → 1.49/scan). ID switch는 그대로였다(459 → 464회).
- 새 변형은 한 번도 실행한 적이 없다. 아래 예측은 결과를 보지 않고 적는다.

## 3. 변형의 정의 (하나뿐)

이름: `ekfh` (EKF + GNN, output held at the last update).

- 필터, gating, 전역 배정, 항적 생성·확정·삭제, 커버리지 밖 삭제 판정은 EKF(`EKFTracker`)와 **완전히 같다**. 연관에는 지금처럼 탐지 시각으로 예측한 상태를 쓴다.
- 달라지는 것은 하나다: scan 끝 시각의 출력 위치가 "마지막 갱신 상태를 그 시각으로 예측한 위치"에서 "마지막 갱신 직후의 위치"로 바뀐다. 코드를 읽어 확인한 사실: EKF 항적의 저장 상태는 마지막 갱신 시각의 상태이고, 탐지가 없던 scan에서는 바뀌지 않는다.
- 조정할 매개변수가 없다.

구성상 EKF와 같아야 하는 것: 항적 수와 번호, 갱신 기록 전체, update-time RMSE와 그 표본. 다르면 구현 오류이므로 멈춘다.

이 설계가 완전한 2 × 2는 아니라는 점을 미리 적는다. "출력 예측"의 내용이 두 줄에서 다르다. 기준선 쪽은 두 점 속도로 외삽하고, EKF 쪽은 필터가 추정한 속도로 예측한다. 그래서 두 순서의 차이에는 속도 추정의 질 차이가 들어 있다.

## 4. 입력, seed, 표본

- 시나리오: 스히폴 평가 구간(`EHAM_1106_eval`) 하나, 기준 조건, 설정은 앞 실험과 같다.
- seed: 20261106–20261125 (20개).
- 방법 네 개: `nn`, `nnp`, `ekfh`, `ekf`. 앞의 세 방법은 표본 기록을 위해 다시 실행하고, 점수가 기존 파일과 같은지 seed마다 확인한다(`nn`, `ekf`는 `results/data/stage2/runs/`, `nnp`는 `results/audit/predict_baseline/runs.json`).
- **네 방법 공통 표본**: 네 방법 모두 2 km 안에 짝이 있는 (seed, scan 번호, 익명 정답 번호)의 교집합. 앞 실험의 세 방법 공통 표본과 다를 수 있으므로 경로 A의 값도 이 표본에서 다시 계산해 함께 적는다.

## 5. 지표

모두 seed로 짝지은 차이의 평균과 95% t-구간(자유도 19). 구간은 고정된 한 교통 구간에서의 시뮬레이션 변동이다.

네 방법 공통 표본의 scan-end RMSE를 R(·)이라 하면:

- 경로 A(앞 실험의 순서): A_pred = R(nnp) − R(nn), A_rest = R(ekf) − R(nnp)
- 경로 B(이번 순서): B_rest = R(ekfh) − R(nn), B_pred = R(ekf) − R(ekfh)
- 전체: D_total = R(ekf) − R(nn)
- 몫: s_A = A_pred / D_total, s_B = B_pred / D_total (seed 평균의 비)
- 함께 보고: 각자의 표본 RMSE와 표본 수, update-time RMSE, ID switch, 끊김, 놓친 표적, 가짜 항적, GOSPA.
- s_A와 s_B는 각 순서에서의 값으로만 적는다. 둘의 평균이나 다른 조합을 "예측의 기여도"로 내세우지 않는다.

## 6. 실행 전 예측과 판정 규칙

예측(에이전트, 결과를 보기 전):

- R(ekfh)는 490–525 m. 필터가 탐지 잡음을 줄여도 scan 끝까지의 지연 오차가 그대로 남기 때문이다.
- 따라서 s_B는 0.9 이상이고, s_A(약 0.6)와 크게 다르다.
- `ekfh`의 놓친 표적은 2.5–4.5/scan, 끊김은 100회 이상으로 늘어난다(출력이 2 km 넘게 뒤처지는 경우).
- `ekfh`의 ID switch는 60회 아래에 머문다.

판정:

- H1(README 문장의 "scan 사이 예측" 부분, 반대 순서에서): B_pred의 95% 구간이 전부 0 아래이고 s_B ≥ 0.5이면 **지지**, 구간이 0 아래이지만 s_B < 0.5이면 **부분 지지**, 그 밖은 **지지하지 않음**.
- H2: |s_B − s_A| ≤ 0.10이면 **순서와 무관하게 비슷함**, 아니면 **순서에 따라 다름**. "순서에 따라 다름"이면 README와 면접 문서에서 59.9%를 단독 수치로 쓰지 않고 두 값을 범위로 함께 적는다.
- H3: 짝 차이(ekfh − ekf)와 구간을 그대로 적는다. 판정 문구는 없다.

## 7. 실행 규칙과 중단 조건

- 실행 명령 하나: `.venv/bin/python scripts/audit_hold_ekf.py`. `ps`로 다른 작업을 확인한 뒤 실행한다.
- 중단 조건:
  - 다시 실행한 `nn`, `ekf`, `nnp`의 점수가 기존 파일과 한 자리라도 다르면 멈춘다.
  - `ekfh`의 update-time RMSE 또는 갱신 표본이 `ekf`와 다르면 멈춘다.
  - 변형을 하나 더 만들고 싶어지면 멈춘다. 결과를 본 뒤 다른 출력 규칙을 추가하지 않는다.
  - 실행이 10분을 넘기면 멈추고 보고한다.
- 하지 않는 것: main 병합, 공개 저장소 반영, 데모 재배포, 사이트 변경, 기존 매개변수 변경, 기존 결과 파일 수정.
