# 설계 메모: 고밀도 클러터에서 JPDA와 MHT (구현하지 않음)

2단계에서는 확정 규칙만 바꿔 봤다(README "고밀도 클러터" 절). 이 메모는 그다음에 시도할 방법의 설계만 적는다. 코드와 결과는 없다.

## 지금 방식(GNN)이 무너지는 이유

- GNN은 scan마다 탐지 하나를 항적 하나에 확정적으로 붙인다. gate 안에 클러터가 여러 개 있으면 가장 싼 하나를 골라 갱신하고, 틀린 선택은 되돌릴 수 없다.
- 가항적은 첫 탐지에서 속도를 모르기 때문에 gate가 넓다(두 번째 scan에서 반경 약 2.7 km). λ 1000(평균 3.2×10⁻² /km²/scan)에서는 이 gate 안에 클러터가 평균 0.7개 들어온다. 클러터끼리 M-of-N 조건을 채우는 일이 흔해진다.

## JPDA (joint probabilistic data association)

- 생각: 탐지를 하나 고르지 않고, gate 안 모든 탐지를 "이 항적의 것일 확률"로 가중해 갱신한다. 여러 항적이 탐지를 공유하면 결합 사건의 확률로 가중치를 구한다.
- 이 프로젝트에 넣는 방법:
  - 연관 단계: 지금의 gate 통과 쌍 목록(`_candidate_pairs` → gating)을 그대로 쓴다. 연결된 묶음(이미 `assign_pairs`가 나누는 단위)마다 결합 사건을 열거한다. 묶음이 크면 사건 수가 폭발하므로 비용이 낮은 상위 K개 배정만 쓰는 근사(Murty)나 주변 확률 근사(LBP)를 쓴다.
  - 가중치: 사건 확률 ∝ ∏ (Pd · N(ν; 0, S) / λ_c) × ∏ (1 − Pd·P_G). 클러터 밀도 λ_c는 이 레이더 모형에서 거리의 함수(1/r)이므로 탐지 위치마다 계산한다.
  - 갱신: 항적별로 가중 혁신 ν̄ = Σ β_j ν_j 로 갱신하고, 공분산에는 "탐지가 없었을 확률" β_0 항과 혁신 퍼짐 항을 더한다(PDA 갱신식).
  - 항적 관리: M-of-N 대신 항적 존재 확률을 함께 추정하는 JIPDA가 자연스럽다. 존재 확률이 임계값을 넘으면 확정, 아래로 내려가면 삭제한다. 클러터에서 생긴 항적은 존재 확률이 오르지 않는다.
- 기대와 위험: 클러터 속 단일 표적의 항적 유지가 좋아진다. 가까운 두 표적은 추정이 서로 끌려가 합쳐질 수 있다(coalescence). 이 데이터에는 평면에서 교차하는 항공기가 많아 이 부작용을 따로 측정해야 한다.
- 검증 계획: 합성 정답에서 β의 합이 1인지, 클러터가 없을 때 GNN과 같은 결과인지, λ 스윕에서 가짜 항적·ID switch·RMSE를 GNN과 짝 비교.

## MHT (multiple hypothesis tracking)

- 생각: 연관 결정을 미룬다. 탐지마다 "기존 항적의 연장 / 새 항적 / 클러터" 가설을 모두 만들고, 몇 scan 뒤 증거가 쌓이면 가능성이 낮은 가지를 버린다.
- 이 프로젝트에 넣는 방법(track-oriented MHT):
  - 항적마다 가설 나무를 둔다. 가지의 점수는 로그 우도비(LLR): 탐지로 갱신하면 ln(Pd · N(ν; 0, S) / λ_c), 누락이면 ln(1 − Pd).
  - 매 scan 전역 가설은 "서로 탐지를 공유하지 않는 가지들의 집합 중 점수 합이 최대인 것"이다. 최대 가중 독립 집합 문제이고, 묶음별로 풀거나 Murty의 K-best 배정으로 근사한다.
  - 가지치기: N-scan pruning(N = 3 정도)과 점수 임계값. 확정·삭제는 LLR에 대한 순차 확률비 검정(SPRT) 임계값으로 한다.
- 기대와 위험: 클러터에서 생긴 가항적은 LLR이 오르지 않아 확정되지 않는다. 교차 상황에서 결정을 미룰 수 있어 ID 유지에 유리하다. 계산량과 구현 복잡도가 크다. λ 1000에서는 scan마다 가설이 수천 개 생기므로 gating과 가지치기 설정이 성능을 좌우한다.
- 검증 계획: 가지치기를 끄고 작은 합성 문제에서 전수 탐색과 같은 전역 가설을 고르는지, N = 1이면 GNN과 같은 결과인지 확인.

## 먼저 해 볼 순서

1. 클러터 밀도를 거리의 함수로 넣은 LLR 기반 항적 점수로 확정·삭제를 바꾼다(GNN 유지). 구현이 가장 작고, M-of-N과 직접 비교할 수 있다.
2. JIPDA.
3. track-oriented MHT.
