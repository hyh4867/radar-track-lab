- A2. scan-end RMSE와 update-time RMSE는 서로 다른 표본에서 계산된다. 두 방법이 모두 값을 가진 공통 표본만 쓰면 두 RMSE의 차이는 어떻게 바뀌는가?

## 2. 이미 본 결과

- 2단계(`results/data/stage2/summary.json`): IMM − EKF와 EKF − 기준선의 짝 차이를 scan-end RMSE와 ID switch에 대해 봤다. 시나리오 15개 모두에서 EKF가 기준선보다 나았다.
- 사용자가 준 확인용 기준값(기준 조건, seed 20개, EKF − 기준선): scan-end RMSE −353.41 m(−355.13 ~ −351.70), update-time RMSE −47.02 m(−47.56 ~ −46.49), ID switch −434.25(−442.45 ~ −426.05). 이 값은 에이전트가 계산한 것이 아니고, 감사 표가 재현해야 할 목표다.
- 표본 단위(탐지·표적-scan)의 오차는 저장한 적이 없고, 공통 표본 분석은 한 번도 하지 않았다.
- 2단계에서 알게 된 것: 기준선의 scan-end 짝은 2 km 안에 추정이 있을 때만 생긴다. 기준선은 표적당 ID switch와 끊김이 많다.

## 3. 코드로 확인한 표본 규칙 (계산 전, 읽기만)

`src/radar_track_lab/sim.py`의 `run()`과 `metrics.py`의 `evaluate_scan()`, `summarize()`:

| | scan-end RMSE (`rmse_m`) | update-time RMSE (`rmse_at_update_m`) |
|---|---|---|
| 시각 | scan k가 끝나는 시각 t_k + T (모든 표적 공통) | 탐지마다 다른 조사 시각 t_k + 방위/ω |
| 추정 상태 | 확정 항적을 그 시각으로 예측한 위치(기준선은 마지막 탐지점) | 탐지로 갱신한 직후의 항적 위치(기준선은 탐지점 그 자체) |
| 정답 | 그 시각에 정답에 있고 커버리지 안인 표적 | 그 탐지를 만든 표적의 조사 시각 상태 |
| 정답 연결 | 전체 표적과 전체 확정 항적 사이의 GOSPA 최적 배정에서 거리 < c(2 km)인 쌍 | 탐지의 출처 표적(`scan.truth_id`). 배정을 거치지 않는다 |
| 포함 조건 | 평가 시각 ≥ 시작 + 60 s | 탐지 시각 ≥ 시작 + 60 s, 갱신 전부터 확정 상태인 항적 |
| 빠지는 것 | 2 km 안에 짝이 없는 표적(놓친 표적)과 항적(가짜 항적) | 클러터가 갱신한 경우, 가항적의 갱신, 탐지가 없던 scan, 탐지가 어느 항적에도 연관되지 않은 경우 |
| 방법 사이 표본 | 방법마다 짝이 생기는 표적-scan이 다르다 | 방법마다 확정 항적에 연관된 탐지가 다르다 |

따라서 두 RMSE는 시각, 상태, 연결 규칙, 표본이 모두 다르다. 기준선은 scan-end에서 2 km 넘게 벗어난 표적이 표본에서 빠지므로 RMSE가 잘린다.

## 4. 표본, 키, seed

- 탐지점은 seed로 정해지고 방법과 무관하다. 그래서 같은 seed에서 탐지 키가 두 방법에 공통이다.
- **update-time 표본 키**: (시나리오, seed, scan 번호, 그 scan 안의 탐지 번호). 부가 값: 익명 정답 번호, 탐지 시각. 두 방법의 같은 키는 정답 번호와 시각이 같아야 하고, 다르면 오류로 처리한다. 한 방법 안에서 키가 중복되면 오류로 처리한다.
- **scan-end 표본 키**: (시나리오, seed, scan 번호, 익명 정답 번호).
- **공통 표본**: update-time은 두 방법 모두 포함 조건을 만족한 키의 교집합. scan-end는 두 방법 모두 짝이 있는 키의 교집합.
- **제외 이유 기록**: update-time은 `clutter`, `tentative`, `warmup` (탐지가 연관되지 않은 경우는 기록이 없으므로 "기록 없음"으로 센다). scan-end는 `warmup`, `unpaired`(2 km 안 짝 없음).
- seed: 20261106–20261125(앞 단계와 같음). 조건: 기준 조건(Pd 0.9, λ 5, σ_θ 0.15°).
- 시나리오: 스히폴 평가 구간과 2단계 표본 밖 시나리오 14개(`results/data/stage2/scenarios.json`). 유효 기준(scan당 5대 이상) 미달 2개는 수치만 적고 A4 비율에서 뺀다.
- 방법: EKF와 기준선. 짝 표(A1)에는 IMM도 넣는다. 공통 표본 분석(A2–A4)은 README 문장이 다루는 EKF 대 기준선만 한다.

## 5. 지표 정의

- 짝 차이: 같은 조건·같은 seed에서 d_s = (EKF 값) − (기준선 값). 보고: 평균, 95% t-구간(자유도 = seed 수 − 1).
- 퍼센트 감소: 100 × (기준선 평균 − EKF 평균) / 기준선 평균. 분모는 기준선의 seed 평균이다. seed별 비의 평균이 아니다.
- 구간의 범위: 정답 궤적은 고정이고 탐지 잡음·누락·클러터만 seed로 바뀐다. 따라서 구간은 **고정된 한 교통 구간에서의 시뮬레이션 변동**만 나타낸다. 다른 날·다른 공항으로의 일반화 불확실성은 들어 있지 않다.
- 공통 표본 RMSE: seed마다 공통 키의 제곱 오차 평균의 제곱근. 방법 간 차이는 seed별 차의 평균과 95% t-구간.
- 함께 보고: GOSPA와 세 성분, 놓친 표적, 가짜 항적, ID switch. 공통 표본은 두 방법 모두 따라간 쉬운 사례에 치우치므로 RMSE만으로 결론을 내지 않는다.
- 보조 기술(판정에 쓰지 않음): scan-end 공통 표본에서 항적의 마지막 갱신 뒤 지난 시간(평가 시각 − 마지막 갱신 시각)별 RMSE.
- 두 원래 RMSE의 차이를 원인별 퍼센트로 나누지 않는다.

## 6. 판정 규칙

- A1 재현: 감사 표의 기준 조건 값이 사용자가 준 기준값과 표시 자릿수(0.01)에서 같으면 "재현". 다르면 차이와 원인을 적는다. seed 집합이 두 방법에서 다르면 그 조건은 계산하지 않고 오류로 적는다.
- A3 (기준 조건, 스히폴 평가 구간). D_se = 공통 표본 scan-end RMSE의 짝 차이, D_up = 공통 표본 update-time RMSE의 짝 차이, D_se0 = 원래 표본 scan-end RMSE의 짝 차이(모두 EKF − 기준선, 음수가 EKF 우세).
  - **유지**: |D_se| ≥ 0.9 × |D_se0| 이고 |D_se| > |D_up| (두 95% 구간이 겹치지 않음).
  - **줄어듦**: |D_se| < 0.9 × |D_se0| 이지만 |D_se| > |D_up| (구간이 겹치지 않음).
  - **뒤집힘**: |D_se| ≤ |D_up| 이거나 두 구간이 겹침.
  - 이 판정은 문장의 앞부분("scan-end에서 차이가 더 크다")만 다룬다. "항적 번호 유지" 부분은 RMSE로 판정할 수 없으므로 ID switch·끊김·놓친 표적 수와 공통 표본에서 빠진 표본 수로 따로 적는다.
- A4: 유효 시나리오마다 같은 판정을 하고, "D_se와 D_up이 모두 음수이고 |D_se| > |D_up|"인 시나리오의 비율을 적는다.

## 7. 실행 규칙

- 평가 경로의 기록은 선택형이다. 기록을 꺼도 켜도 기존 점수(`summary`)가 같아야 하고, 이것을 test로 확인한다. 기존 결과 파일은 다시 쓰지 않는다.
- 짝 표는 기존 CSV/JSON만 읽는 가벼운 명령 하나로 다시 만든다: `.venv/bin/python scripts/audit_paired.py`.
- 표본 기록 실행(시나리오 15개 × 방법 2개 × seed 20개)은 `ps`로 다른 세션을 확인한 뒤 한 번에 하나, `screen` + `caffeinate -i`, 시나리오 단위 체크포인트.
- 중단 조건: 기록을 켠 실행의 요약이 기존 결과 파일과 다르면 멈추고 원인을 찾는다. 한 작업이 1시간을 넘기면 멈추고 보고한다.
- 하지 않는 것: main 병합, 공개 저장소 반영, 데모 재배포, 사이트 변경, 매개변수 변경.
