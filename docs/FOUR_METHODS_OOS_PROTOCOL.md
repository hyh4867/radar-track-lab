# Radar Track Lab: 네 방법을 다른 공항·날짜에 돌리는 실험 프로토콜

작성: 2026-11-20, 실행 스크립트를 쓰거나 실행하기 전. 이 파일을 커밋한 뒤에 실행한다.
범위는 앞 단계와 같다: 민간 항공기만, 식별자 저장 안 함, 군용·LADD·PIA 제외. 기존 결과 파일(`results/data/`, `results/RESULTS.md`, `results/audit/`의 기존 파일 전부)과 데모 자료는 고치지 않는다. 새 산출물은 `results/audit/four_methods_oos/`에 둔다.

## 1. 질문

앞의 두 실험(`docs/PREDICT_BASELINE_PROTOCOL.md`, `docs/HOLD_EKF_PROTOCOL.md`)은 스히폴 평가 구간 하나에서 나온 결과다.

- G1. 출력 예측 단계가 두 순서 모두에서 scan-end RMSE 차이의 절반 이상이라는 결과가 다른 공항·시간대·날짜에서도 나오는가?
- G2. 두 순서의 몫이 크게 다르다는 결과(59.7% 대 97.1%)가 다른 곳에서도 나오는가?
- G3. "출력 예측을 뺀 EKF는 이 지표에서 기준선과 거의 같다"(차이 10 m, 전체의 2.9%)가 다른 곳에서도 나오는가?

## 2. 이미 본 결과

- 스히폴 평가 구간, 네 방법 공통 표본의 scan-end RMSE: 기준선 526.4 m, 기준선 + 출력 예측 315.6 m, EKF(출력 예측 없음) 516.3 m, EKF 173.0 m. 몫 s_A = 59.7%, s_B = 97.1%.
- 2단계와 3단계에서 다른 시나리오 14개에 대해 기준선과 EKF를 돌린 결과(`results/data/stage2/runs/`, `results/audit/sample_audit.md`). 유효 시나리오 12개 모두에서 EKF가 기준선보다 나았다. 시나리오별 EKF와 기준선의 RMSE는 이미 봤다.
- `nnp`와 `ekfh`는 스히폴 평가 구간 밖에서 한 번도 실행한 적이 없다. 아래 예측은 그 결과를 보지 않고 적는다.

## 3. 방법, 입력, seed

- 방법 네 개, 정의는 앞 프로토콜과 같고 바꾸지 않는다: `nn`, `nnp`, `ekfh`, `ekf`. 새 변형은 없다. 매개변수는 2단계에서 동결한 값 그대로다.
- 시나리오: `results/data/stage2/scenarios.json`에서 2단계에 실제로 돌린 표본 밖 시나리오 14개(스히폴의 다른 시간대 3개, 다른 공항 5곳의 2026-11-06 구간, 2026-11-11의 스히폴과 공항 5곳). 조정 구간과 예비 공항(실행하지 않음)은 뺀다.
- 유효 기준은 2단계와 같다: scan당 정답 표적 평균 5대 이상. 3단계 감사에서 이 기준으로 12개가 유효였다. 유효하지 않은 2개는 수치만 적고 아래 비율에서 뺀다.
- seed: 20261106–20261125 (20개), 기준 조건(Pd 0.9, λ 5, σ_θ 0.15°).
- 스히폴 평가 구간은 다시 돌리지 않는다. 표에는 `results/audit/hold_ekf/summary.json`의 값을 참고 줄로 넣되 비율에는 넣지 않는다.

## 4. 지표

시나리오마다, 네 방법 공통 표본의 scan-end RMSE를 R(·)이라 하고 seed로 짝지은 차이의 평균과 95% t-구간(자유도 19)을 구한다.

- A_pred = R(nnp) − R(nn), B_pred = R(ekf) − R(ekfh), B_rest = R(ekfh) − R(nn), D_total = R(ekf) − R(nn)
- s_A = A_pred / D_total, s_B = B_pred / D_total (seed 평균의 비)
- 함께 보고: 공통 표본 수, 각자의 표본 RMSE, ID switch, 끊김, 놓친 표적.
- 구간의 의미: 시나리오 안의 구간은 그 교통 구간을 고정한 시뮬레이션 변동이다. 시나리오 사이의 퍼짐은 값의 범위(최소–최대)와 개수로만 적고, 12개를 독립 표본으로 본 구간이나 검정은 만들지 않는다. 같은 공항의 두 날, 같은 날의 여러 공항은 서로 독립이 아니다.

## 5. 실행 전 예측과 판정 규칙

예측(에이전트, 결과를 보기 전):

- s_B는 유효 12개 모두에서 0.9 이상.
- s_A는 유효 12개 중 10개 이상에서 0.45–0.75. 교통량이 적거나 느린 항공기가 많은 구간에서는 이 범위를 벗어날 수 있다.
- 두 순서의 몫 차이는 12개 모두에서 0.10보다 크다.
- |B_rest|는 12개 모두에서 |D_total|의 10% 이하.

시나리오별 판정(앞 프로토콜과 같은 규칙):

- 순서 A 지지: A_pred의 구간이 전부 0 아래이고 s_A ≥ 0.5. 순서 B 지지: B_pred의 구간이 전부 0 아래이고 s_B ≥ 0.5.
- 순서 의존: |s_B − s_A| > 0.10.
- 기준선과 거의 같음: |B_rest| ≤ 0.10 × |D_total|.

전체 판정(유효 12개 가운데 개수로):

- G1: 두 순서 모두 지지인 시나리오가 10개 이상이면 **다른 곳에서도 성립**, 6–9개이면 **일부에서만 성립**, 5개 이하이면 **성립하지 않음**.
- G2: 순서 의존인 시나리오 수에 같은 구분을 쓴다.
- G3: 기준선과 거의 같음인 시나리오 수에 같은 구분을 쓴다.
- 어느 판정이든 개수와 시나리오별 값을 그대로 표에 적는다. 성립하지 않는 시나리오는 이름을 적는다.

## 6. 실행 규칙과 중단 조건

- 실행 명령 하나: `.venv/bin/python scripts/audit_four_methods_oos.py`. `ps`로 다른 작업을 확인한 뒤 `screen` + `caffeinate -i`로 하나만 돌린다. 시나리오 단위 체크포인트.
- 중단 조건:
  - 다시 실행한 `nn`, `ekf`의 점수가 2단계 결과 파일과 한 자리라도 다르면 멈춘다.
  - `nnp`의 갱신 표본이 `nn`과, `ekfh`의 갱신 표본이 `ekf`와 다르면 멈춘다.
  - 변형이나 판정 규칙을 바꾸고 싶어지면 멈춘다.
  - 실행이 1시간을 넘기면 멈추고 보고한다.
- 하지 않는 것: main 병합, 공개 저장소 반영, 데모 재배포, 사이트 변경, 매개변수 변경, 기존 결과 파일 수정.
