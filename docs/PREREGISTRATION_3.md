## 2. 공통 규칙

- **seed**: 평가 20261106–20261125(20개, 1·2단계와 같음). 조정 20271106부터.
- **짝 비교**: 같은 seed, 같은 교통. 두 방법(또는 두 센서 모형)의 차이는 seed별 차의 평균과 95% t-구간. 센서 모형이 바뀌면 같은 seed라도 난수 소비가 달라 탐지점이 같지 않다. 이때 짝은 "같은 교통, 같은 seed 번호"라는 뜻이다.
- **공통 표본**: RMSE는 비교하는 모든 방법(그리고 비교하는 모든 센서 모형)에서 정답에 있고 짝이 있는 표적-scan으로만 낸다. 각자의 표본 값도 함께 적는다.
- **유효 시나리오**: 2단계와 같은 12개(이상적 모형에서 scan당 정답 ≥ 5대). 새 모형에서 정답 수가 줄어도 유효 목록은 바꾸지 않는다.
- **헤드라인 수치 재계산**: 보고서의 헤드라인 수치는 run 파일만 읽는 별도 스크립트(`scripts/stage3_recompute.py`, 분석 모듈을 import하지 않음)로 다시 계산해 소수 둘째 자리까지 일치를 보인다.
- **퇴행 없음**: 새 요소를 모두 끄고 앞단 걸러내기를 옛 6 km로 두면 1·2단계 run 파일이 seed별로 똑같이 재현되어야 한다(상대 차 1e-9 이하). 구현 뒤 다시 확인한다. 새 요소를 끈 상태의 난수 소비는 바꾸지 않는다.

### 3.3 단위 시험 (손 계산과 대조; 실데이터 실행 전에 통과해야 함)

- E1: P_fa 10⁻⁶에서 SNR 130.1(21.14 dB)이면 Pd 0.900, SNR 0이면 Pd 10⁻⁶. 지수분포 전력 Monte Carlo(10⁶ 표본)가 식과 3σ 안에서 일치. SNR(R)의 R⁻⁴(거리 2배 → SNR 1/16).
- E1 보정: 작은 거리 목록에 대해 보정 결과가 brentq 없이 손으로 푼 값과 같음.
- E2: 수평선 거리 h_t 1,609 m, h_r 0 → 165.3 km(Wikipedia 예 164 km), h_t 23 m → 19.8 km(19 km). 지상 5 km, 고도 10 km → 고각 약 63.4°(원뿔 안). 지상 50 km, 고도 3 km → 경사 거리를 구면 식과 평면 근사로 계산해 차이가 수 m 이하. 경사 → 지상 변환을 정확한 고도로 하면 왕복 오차 < 1 mm.
- E3: 10⁶개 표본에서 세 성분 비율(60/30/10%)과 근거리 성분의 거리 평균(1 km + 8 km, 100 km에서 자른 효과 포함)이 3σ 안. 클러터 지도가 run 사이에 같고 공항 사이에 다름.
- E4: 거리 100 m·방위 1.0° 떨어진 두 표적 → 보고 1개, 위치는 평균. 거리 200 m → 2개. 방위 1.5° → 2개. 셋이 사슬처럼 이어지면 1개(단일 연결). 하나만 탐지되면 그 표적의 위치.
- 퇴행: 요소를 모두 끈 M0이 1·2단계 run 파일을 seed별로 똑같이 재현.

### 3.4 실행

- 방법 5개: 기준선(nn), 기준선 + 출력 예측(nnp), EKF(출력 예측 없음, ekfh), EKF, IMM.
- 구간 13개: 스히폴 평가 구간 + 표본 밖 유효 12개(유효하지 않은 2개는 수치만).
- 모형 5개(M0–M4) × 방법 5개 × 구간 13개 × seed 20개. 앞단 걸러내기는 B0에서 고친 판으로 모두 같게 둔다(그래서 M0 수치는 2단계와 조금 다를 수 있고, 그 차이는 B0에 적는다).
- ID switch 원인 분류는 2단계 정의 그대로(`diagnose.py`).

### 3.5 대상 결론과 판정 규칙

**C1. IMM이 ID switch를 줄인다 (그리고 EKF가 기준선보다 낫다).**
- 스히폴: ID switch 짝 차이(IMM − EKF) 95% 구간이 전부 0 아래.
- 표본 밖: 2단계 Q4 규칙 그대로 시나리오별 "IMM 이득 유지" = ID switch 짝 차이(IMM − EKF) 95% 구간이 0 아래이고 RMSE 비(IMM/EKF) ≤ 1.05.
- 판정: 스히폴 성립 + 표본 밖 10곳 이상 → **유지**. 스히폴 성립 + 6–9곳 → **부분 유지**. 그 밖 → **깨짐**.
- 함께: "EKF가 기준선보다 낫다"(2단계 Q4 규칙: RMSE와 ID switch 짝 차이 구간 둘 다 0 아래)를 같은 방식으로 센다.

**C2. 실패가 선회에 몰린다.**
- 2단계 Q1 규칙 그대로: EKF의 "표적이 있는데 잃음" ID switch 중 `turn` 비율(seed 20개 합산)이 50% 이상이고 기저율의 2배 이상이면 "선회가 주원인", 30% 미만이면 "주원인 아님", 그 사이는 "부분적".
- 스히폴과 표본 밖 유효 12개 합산에 각각 적용. 둘 다 "선회가 주원인" → **유지**. 하나만 → **부분 유지**. 둘 다 아님 → **깨짐**.
- 함께: 원인별 개수, 특히 `misses`와 새 범주가 아닌 기존 범주에서의 변화. 2단계에서 잃음의 68%를 만든 두 항공기를 뺀 값도 적는다(판정 대상 아님).

**C3. 스캔 끝 RMSE 분해의 모양.**
- 네 방법(nn, nnp, ekfh, ekf) 공통 표본 scan-end RMSE로, `docs/FOUR_METHODS_OOS_PROTOCOL.md`의 G1–G3 그대로:
  - G1: 출력 예측 단계가 두 순서 모두에서 전체 차이의 절반 이상.
  - G2: 두 순서의 몫이 10%p 넘게 다름.
  - G3: 출력 예측 없는 EKF와 기준선의 차이가 전체의 10% 이하.
- 표본 밖 유효 12개 중 10개 이상에서 셋 모두 성립하고 스히폴에서도 성립 → **유지**. 하나라도 6–9개 → **부분 유지**. 하나라도 5개 이하 → **깨짐**.
- 함께: 상호작용 항(2×2 배치)의 몫. 판정 대상 아님.

### 3.6 예측 (Claude)

- **C1 유지.** M4 스히폴에서 EKF ID switch는 24.9 → 40–80(먼 거리 낮은 Pd 때문에 끊긴 뒤 다시 잡는 경우가 늘어남), IMM − EKF 차이는 −5 ~ −15회로 구간이 0 아래. 표본 밖 10–12곳 유지. EKF > 기준선은 12/12.
- **C2 깨짐 또는 부분 유지.** 직선 비행 중 먼 거리 연속 누락으로 잃는 경우가 늘어, 스히폴 EKF의 `turn` 비율이 2단계의 99%에서 20–45%로 떨어지고 `misses`가 가장 큰 원인이 될 것. 기저율(약 19%)은 거의 그대로.
- **C3 유지.** 12/12. 순서 A의 몫은 탐지 사이 시간이 길어져 M0보다 0–10%p 올라가고, 순서 B는 0.9 이상 유지.
- 요소별: E1이 ID switch와 놓친 표적을 가장 크게 바꿈. E2는 원뿔(0.1% 미만)과 수평선(정답에서 빠짐)이라 추적 지표 변화는 작음(ID switch ±3회). E2 보조(경사 거리 보정 없음)는 EKF scan-end RMSE를 +30 ~ +100 m 올림. E3은 λ 5에서는 거의 영향 없음(가짜 항적 ±0.3/scan). E4는 접근 경로에서 ID switch를 +1 ~ +5회.

## 4. B. 조밀한 클러터와 앞단 걸러내기

### 4.1 B0. 6 km 한도 고치기 (먼저)

- 지금: 항적과 탐지점의 선형 예측 거리 6 km 밖은 χ² gate 검사 없이 버린다. 한 scan을 놓친 가항적의 gate(7–8 km)보다 좁다.
- 고침: 고정 한도 대신 항적마다 반지름을 계산한다. r_i = √(γ · λ_max(P_pos,i(Δt_max) + R_cart,max)) + 1 m. γ는 gate 문턱, Δt_max는 마지막 갱신부터 이번 scan 끝까지, R_cart,max는 최대 거리에서 측정 공분산의 최대 고유값. 이 반지름은 실제 gate를 항상 포함하므로 결과가 "앞단 걸러내기 없음"과 같아야 한다.
- 단위 시험: 무작위 항적·탐지 집합(가항적, 놓친 scan 포함)에서 새 앞단 걸러내기 + gate의 결과 = 걸러내기 없이 모든 쌍에 gate를 건 결과.
- 보고: 같은 seed로 고치기 전(6 km)·후의 지표 짝 차이. EKF와 IMM, 스히폴 λ 5·200·1000과 표본 밖 13개 구간(λ 5).
- 예측: λ 5에서 시나리오별 ID switch 변화 |Δ| < 0.3회, GOSPA 변화 < 0.1%(2단계 12 km 결과와 같음). λ 1000에서 EKF 가짜 항적 변화 ±5% 안. 실행 시간은 λ 1000에서 +0–30%.

### 4.2 B1. 확률적 연관과 존재 확률

세 추적기(모두 같은 EKF NCV, q = 25, 같은 gate 0.999, 같은 단일점 시작과 초기 속도 표준편차 150 m/s):

| 이름 | 연관 | 항적 관리 |
|---|---|---|
| GNN | 지금(헝가리안, d² + ln|S|) | 3/4 확정, 5회 누락 삭제 |
| JPDA | 결합 확률적 연관. 갱신은 가중 혁신 + 혁신 퍼짐 항 | 3/4 확정, 5회 누락 삭제. "적중" = gate 안에 탐지점이 하나 이상 |
| JIPDA | JPDA + 항적 존재 확률(Markov chain 1) | 존재 확률로 확정·삭제(문턱은 조정) |

- 클러터 밀도: 추적기가 참 밀도를 안다고 둔다(이상화). 균일 조건은 측정 공간에서 λ / ((R_max − R_min) · 2π) [1/(m·rad)], 클러터 지도 조건은 E3 지도의 밀도.
- Pd 가정 0.9, gate 확률 P_G 0.999.
- 결합 사건 계산: gate로 묶인 항적-탐지 덩어리마다. 항적 ≤ 10개이고 사건 수 ≤ 10⁵이면 정확히 열거, 그보다 크면 loopy belief propagation(Williams & Lau 2014)으로 근사. 근사를 쓴 덩어리 비율을 적는다.
- JIPDA 존재 확률(Musicki & Evans 2004의 표준 형태, 원문은 다시 읽지 않았고 손 계산 시험으로 확인): 예측 P⁻ = p_s · P, p_s = 0.98/scan(고정). 갱신 δ = P_D P_G (1 − Σ_j ℓ_j/ρ_j), P⁺ = (1 − δ) P⁻ / (1 − δ P⁻). 결합 사건에서는 각 항적의 주변 확률로 계산한다.
- 새 항적: 기존 항적들에 대한 연관 확률 합이 0.5 미만인 탐지점에서 시작(세 추적기 모두; GNN은 지금처럼 "배정되지 않은 탐지점").
- JIPDA 조정(조정 구간, seed 20271106–20271110, 5개): 초기 존재 확률 {0.01, 0.05, 0.1, 0.2} × 확정 문턱 {0.9, 0.95, 0.99} × 삭제 문턱 {0.01, 0.05} = 24개, λ {5, 200, 1000} 균일. 선택: λ 5 GOSPA가 GNN(조정 구간)의 1.02배 이하인 조합 중 λ 200과 1000의 평균 GOSPA 합이 가장 작은 것. 없으면 λ 5 GOSPA가 가장 작은 조합을 쓰고 적는다. 조정 뒤 `configs/stage3.yaml`에 동결하고 커밋한 다음 평가한다.

### 4.3 조건, 지표, 판정

- 조건: 스히폴 평가 구간, seed 20개, 이상적 측정 모형에서 클러터 λ 5, 200, 1000(균일)과 같은 λ의 E3 클러터 지도 = 6조건 × 추적기 3개.
- 지표: GOSPA와 성분(위치·놓침·가짜), ID switch, scan당 가짜 항적, 확정 지연(첫 정답 출현부터 확정까지, 1단계 `init_delay_mean_s`), run당 실행 시간.
- NEES: 모델이 맞는 합성 NCV 정답(`synthetic.ncv_scenario`, 표적 40대, Pd 0.9)에서 λ 5, 200, 1000 균일, 세 추적기의 확정 항적 4차원 평균 NEES.
- 판정 (JIPDA의 목표 "시작 단계의 클러터 확정을 줄임"):
  - λ 1000 균일과 λ 1000 지도 둘 다에서 scan당 가짜 항적과 GOSPA의 짝 차이(JIPDA − GNN) 95% 구간이 전부 0 아래이고, λ 5 균일에서 GOSPA 비(JIPDA/GNN) 95% 구간 상한 ≤ 1.02, 확정 지연 차 ≤ +5 s → **개선**. λ 1000에서만 개선이고 λ 5 조건을 못 맞추면 **대가 있는 개선**. λ 1000에서 개선이 없으면 **개선 없음**.
  - JPDA(− GNN)는 같은 표로 기술만 한다.
- 예측(Claude):
  - GNN λ 1000 균일 가짜 항적 약 555/scan(2단계 재현) → JIPDA 1–10/scan. GOSPA −60 ~ −80%. λ 1000 지도에서도 JIPDA ≤ 20/scan.
  - JPDA(3/4 관리)는 시작 단계가 같아 λ 1000 가짜 항적을 0–30%만 줄임.
  - λ 5에서 JIPDA 확정 지연은 GNN 대비 +0 ~ +5 s, GOSPA 비 0.97–1.02. 판정 **개선**.
  - 합성 NEES: λ 5에서 세 추적기 4.0–4.6, λ 1000에서 JPDA·JIPDA ≤ 6, GNN은 잘못된 연관 때문에 더 큼.
  - 실행 시간: λ 1000에서 JIPDA는 GNN의 3–10배.

### 4.4 Stone Soup 교차 확인

- 대상: Stone Soup 1.9.1의 `PDAHypothesiser`, `PDA`, `JPDA`(정확 열거), `JPDAwithLBP`, `PDAUpdater`. **Stone Soup 1.9.1에는 가우시안 IPDA/JIPDA가 없다**(존재 확률은 입자 필터 쪽에만 있음). 그래서 JIPDA의 존재 확률 부분은 손 계산 시험으로만 확인하고, 연관·갱신 부분은 존재 확률을 1로 고정한 경우(=JPDA)로 Stone Soup과 대조한다.
- 2단계와 같이 Stone Soup의 수치 Jacobian 문제를 피하려 +200 km 이동 좌표에서 비교한다.
- (a) 한 scan 대조: 같은 예측 항적·탐지점·클러터 밀도·P_D·P_G. 평가 구간에서 뽑은 장면(λ 5, 200, 1000)과 손으로 만든 덩어리(항적 2–6개가 탐지점을 공유). "일치" = 연관 확률 상대 차 ≤ 1e-6(LBP는 수렴 허용치 때문에 ≤ 1e-4), 갱신 위치 차 ≤ 1 cm, 공분산 상대 차 ≤ 1e-6.
- (b) 추적기 대조: 우리 항적 관리 위에 Stone Soup의 JPDA 연관과 PDA 갱신을 올려, 스히폴 평가 구간 λ 5와 200, seed 3개. λ 1000은 Stone Soup 정확 열거가 너무 느리면 앞 5분만. "같은 답" = 확정 항적-scan의 99.9% 이상에서 위치 차 ≤ 1 cm이고 ID switch 수가 같음.
- 다르면 처음 갈라진 scan을 찾아 원인(클러터 밀도 단위, P_G 정규화, gate, 시각, 덩어리 분할)을 적는다.
- 예측: (a)는 정규화 방식 하나를 맞춘 뒤 일치. 첫 비교에서는 Stone Soup이 가설 가중치에 P_G를 넣는 방식 때문에 불일치가 한 번 나올 것. (b)는 λ 5와 200에서 같은 답.

### 7.2 Mode C 100 ft 양자화의 출처

- 확인함: ICAO Annex 10 Volume IV 3.1.1.7.12.2.3 "Pressure-altitude shall be reported in 100-ft increments by selection of pulses as shown in the Appendix to this chapter." 같은 절 3.1.1.7.12.2.2는 기준 기압을 표준 기압 1,013.25 hPa로, 3.1.1.7.12.2.4는 디지타이저 부호가 기압 고도와 95% 확률로 ±38.1 m(125 ft) 안에서 일치할 것을 정한다.
- 확인한 문서: ICAO 원문(유료)이 아니라, Annex 10 Vol IV를 Amendment 92까지 그대로 옮긴 피지 민간항공청 SD-ATELCOM Vol IV(Edition 1.0, 2025/2026, 절 번호 동일). https://www.caaf.org.fj/wp-content/uploads/2026/07/SD_ATELCOM_VOL-IV_Amendment-92-to-A10-Vol-IV_v0.2.pdf (2026-11-21 PDF 본문에서 확인).
- 그래서 3.1절 E2의 "100 ft 양자화는 출처를 확인하지 못한 가정"은 "ICAO Annex 10 Vol IV 3.1.1.7.12.2.3(옮긴 문서로 확인)"으로 바꿔 읽는다.
- 모형에 넣지 않는 것: 디지타이저 오차(±125 ft, 95%). 정답 고도 자체가 ADS-B 기압 고도라서 표준 기압 기준은 Mode C와 같지만, 기하 고도와의 차(QNH)는 정답과 측정 모두에 들어가지 않는다.

### 7.3 클러터 밀도를 자료에서 추정하는 JIPDA (설명용, 판정 대상 아님)

- 시스템 여유 메모리가 15% 아래면 새 작업(새 screen 작업, 그리고 실행 스크립트 안의 다음 조건·구간 단위)을 시작하지 않고 15% 이상이 될 때까지 기다린다. 5.의 "10% 미만이면 기다림"을 이 규칙이 대신한다. 기다린 시간은 보고서에 적는다.

### 7.5 실행 방식 변경 (2026-11-22 13:15 KST, 사용자 승인)

- 실행 방식만 변경(대기열 해제), 설정·판정 기준 변경 없음. 이번 3단계 종료까지 `tools/heavy-run.sh` 대기열을 거치지 않고 직접 실행할 수 있다(드론 세션과 동시 실행 허용). 새 작업을 시작하기 전마다 `sysctl vm.swapusage`와 `memory_pressure | tail -1`을 `results/stage3/logs/unlock_safety.log`에 남기고, 스왑 > 3 GB 또는 여유 < 10%면 시작하지 않는다. 이미 잠금을 잡고 실행 중이던 B 작업 5는 그대로 둔다.
