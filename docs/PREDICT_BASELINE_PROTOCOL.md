# Radar Track Lab: 예측만 붙인 기준선 실험 프로토콜

작성: 2026-11-20, 새 변형을 구현하거나 실행하기 전. 이 파일을 커밋한 뒤에 코드를 쓰고 실행한다.
범위는 앞 단계와 같다: 민간 항공기만, 식별자 저장 안 함, 군용·LADD·PIA 제외. 기존 결과 파일(`results/data/`, `results/RESULTS.md`, `results/audit/`의 기존 파일)과 데모 자료(`web/`, `results/thumbnails/`)는 고치지 않는다. 새 산출물은 `results/audit/predict_baseline/`에 둔다.

## 1. 질문

3단계 감사(`docs/AUDIT_PROTOCOL.md`, `results/audit/sample_audit.md`)는 README의 문장 "큰 차이는 scan 사이 예측과 항적 번호 유지에서 나옵니다" 가운데 "예측" 부분을 관찰과 맞는 설명으로만 남겼다. 예측만 따로 떼어 본 실험이 없었기 때문이다.

- P1. 기준선의 연관과 항적 관리는 그대로 두고 **출력에만 직선 외삽을 붙이면** scan-end RMSE가 얼마나 줄어드는가?
- P2. 그 줄어든 양은 EKF와 기준선의 차이(공통 표본에서 −353.9 m) 중 어느 정도인가? 남는 차이는 얼마인가?
- P3. 항적 번호 지표(ID switch, 끊김, 놓친 표적)는 기준선과 달라지는가?

## 2. 이미 본 결과

- 스히폴 평가 구간, seed 20개: scan-end RMSE는 기준선 528.1 m, EKF 174.7 m. 공통 표본에서 528.2 m 대 174.2 m, 짝 차이 −353.93 m [−355.64, −352.22]. update-time RMSE는 172.8 m 대 125.8 m.
- 기준선의 scan-end 오차는 마지막 탐지 뒤 지난 시간에 따라 204 m에서 617 m로 커진다(`results/audit/sample_audit.md`). EKF는 119 m에서 200 m.
- ID switch 459.2 대 24.9, 끊김 414.2 대 3.6, 놓친 표적 4.02 대 0.82 /scan.
- 새 변형은 한 번도 실행한 적이 없다. 아래 예측은 결과를 보지 않고 적는다.

## 3. 변형의 정의 (하나뿐)

이름: `nnp` (nearest-neighbour baseline + output prediction).

- 연관, 항적 생성·확정·삭제, 커버리지 밖 삭제 판정은 기준선(`NearestNeighborBaseline`)과 **완전히 같다**. 연관은 지금처럼 항적의 마지막 탐지점과 새 탐지점 사이의 거리(2 km 한도, 가까운 순서)로 한다. 예측 위치를 연관에 쓰지 않는다.
- 속도는 기준선이 이미 계산해 두는 값을 그대로 쓴다: 항적에 연결된 최근 두 탐지점의 위치 차를 두 탐지 시각의 차로 나눈 것(`tracker.py`의 `_update`, 지금까지는 화면 표시에만 썼다). 평활, 속도 상한, 시간 간격 하한 같은 보호 장치를 새로 넣지 않는다.
- 달라지는 것은 하나다: scan 끝 시각 t의 출력 위치가 "마지막 탐지점"에서 "마지막 탐지점 + 속도 × (t − 마지막 탐지 시각)"으로 바뀐다.
- 조정할 매개변수가 없다. 조정 구간을 쓰지 않는다.

따라서 구성상 기준선과 같아야 하는 것: 항적 수와 번호, 갱신 기록 전체, update-time RMSE, 그리고 update-time 표본. 이것이 한 자리라도 다르면 구현 오류이므로 멈춘다(7절).

코드를 읽어 미리 아는 약점(고치지 않고 그대로 둔다):

- 두 점 속도는 탐지 잡음을 그대로 받는다. 거리 50 km에서 방위 잡음은 약 131 m이고 scan 간격이 4.8 s이므로 속도 오차는 축당 수십 m/s 수준이다.
- 기준선이 다른 표적이나 클러터에 잘못 연결되면 속도가 크게 틀린다(최대 2 km / 4.8 s ≈ 417 m/s).
- 정북 방향을 지나는 표적은 연속한 두 scan에서 탐지 시각의 차가 매우 짧을 수 있고, 이때 두 점 속도가 매우 커진다. 외삽한 위치가 2 km 넘게 벗어나면 그 표본은 RMSE에서 빠지고 놓친 표적과 가짜 항적으로 세어진다. 그래서 RMSE만 보지 않는다(5절).

## 4. 입력, seed, 표본

- 시나리오: 스히폴 평가 구간(`EHAM_1106_eval`, 2026-11-06 12:45 UTC부터 30분) 하나. 조건은 기준 조건(Pd 0.9, λ 5, σ_θ 0.15°). 설정은 2단계와 같은 `configs/default.yaml` + `configs/stage2.yaml`.
- seed: 20261106–20261125 (20개, 앞 단계와 같음).
- 방법: 기준선(`nn`), 변형(`nnp`), EKF(`ekf`). 기준선과 EKF는 표본 기록을 위해 다시 실행하되, 점수가 2단계 결과 파일(`results/data/stage2/runs/EHAM_1106_eval__{nn,ekf}.json`)과 같은지 seed마다 확인한다.
- scan-end 표본 키는 감사와 같다: (seed, scan 번호, 익명 정답 번호). **세 방법 공통 표본**은 세 방법 모두 2 km 안에 짝이 있는 키의 교집합이다.
- 다른 공항·날짜에는 이번에 돌리지 않는다. 이 실험의 결론은 스히폴 평가 구간 하나에 대한 것이다.

## 5. 지표

모두 seed로 짝지은 차이의 평균과 95% t-구간(자유도 19). 구간의 의미는 감사와 같다: 고정된 한 교통 구간에서 탐지 잡음·누락·클러터만 바꾼 시뮬레이션 변동.

- 주 지표: 세 방법 공통 표본의 scan-end RMSE.
  - D_pred = RMSE(nnp) − RMSE(nn)
  - D_rest = RMSE(ekf) − RMSE(nnp)
  - D_total = RMSE(ekf) − RMSE(nn)  (D_pred + D_rest와 같다)
- 각자의 표본에서의 scan-end RMSE와 표본 수(세 방법, 공통, 한 방법만, 모두 없음).
- 함께 보고: GOSPA와 세 성분, 놓친 표적, 가짜 항적, ID switch, 끊김. 변형이 외삽 실패로 표본을 잃으면 RMSE는 좋아 보여도 놓친 표적이 늘기 때문이다.
- 보조 기술(판정에 쓰지 않음): 공통 표본에서 마지막 탐지 뒤 지난 시간별 RMSE(감사와 같은 구간 경계 0, 1.2, 2.4, 3.6, 4.8, 9.6 s), 그리고 변형의 항적 속도 크기가 350 m/s 이상인 표본의 수와 그 표본의 RMSE. 350 m/s는 이 문서를 쓰는 시점에 정한 기술용 경계이고 변형의 동작에는 쓰지 않는다.
- D_pred / D_total의 비는 "기준선 → 출력 예측 추가 → EKF" 순서로 한 단계씩 바꿨을 때의 값으로만 적는다. 원인별 기여도로 일반화하지 않는다. 순서를 바꾸면(예: 연관을 먼저 바꾸면) 값이 달라질 수 있다.

## 6. 실행 전 예측과 판정 규칙

예측(에이전트, 결과를 보기 전):

- 변형의 scan-end RMSE(공통 표본)는 기준선보다 낮고 EKF보다 높다. 대략 220–320 m.
- D_pred는 D_total의 절반 이상이다.
- ID switch와 끊김은 기준선과 10% 안에서 같다. 연관이 같기 때문이다.
- 놓친 표적과 가짜 항적은 기준선보다 조금 늘어난다(외삽이 2 km 넘게 벗어나는 경우).

판정(README 문장의 "scan 사이 예측" 부분, 스히폴 평가 구간에 한정):

- **지지**: D_pred의 95% 구간이 전부 0 아래이고 |D_pred| ≥ 0.5 × |D_total|.
- **부분 지지**: D_pred의 95% 구간이 전부 0 아래이지만 |D_pred| < 0.5 × |D_total|.
- **지지하지 않음**: D_pred의 95% 구간이 0을 포함하거나 0 위.
- 이 판정과 별개로, 변형의 놓친 표적 수(평균/scan)가 기준선보다 10% 넘게 늘면 "RMSE 개선의 일부는 표본 탈락과 함께 일어났다"는 단서를 결론에 붙인다.
- P3: ID switch와 끊김의 짝 차이(nnp − nn)와 구간을 그대로 적는다. 판정 문구는 없다.

## 7. 실행 규칙과 중단 조건

- 실행 명령 하나: `.venv/bin/python scripts/audit_predict_baseline.py`. `ps`로 다른 작업을 확인한 뒤 실행한다.
- 중단 조건:
  - 다시 실행한 기준선이나 EKF의 점수가 2단계 결과 파일과 한 자리라도 다르면 멈추고 원인을 찾는다.
  - 변형의 update-time RMSE 또는 갱신 표본이 기준선과 다르면 멈춘다(3절).
  - 변형을 하나 더 만들고 싶어지면 멈춘다. 이 프로토콜은 변형 하나만 허용한다. 결과를 본 뒤 보호 장치를 넣거나 연관에 예측을 쓰는 변형을 추가하지 않는다. 그런 것은 다음 제안으로만 적는다.
  - 실행이 10분을 넘기면 멈추고 보고한다.
- 하지 않는 것: main 병합, 공개 저장소 반영, 데모 재배포, 사이트 변경, 기존 매개변수 변경, 기존 결과 파일 수정.
