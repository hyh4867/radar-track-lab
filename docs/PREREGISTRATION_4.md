## 2. 방법: JIPDA-map

- 연관, 존재 확률, 확정·삭제 문턱, 새 항적 규칙은 모두 3단계 동결값 그대로다(`configs/stage3.yaml`의 `jipda`: p0 0.01, confirm 0.95, delete 0.01, p_survive 0.98, pd 0.9). 바꾸는 것은 클러터 밀도 ρ(z)를 어디서 얻는지 하나뿐이다.
- 추정기 `ClutterMapDensity`(`src/radar_track_lab/jpda.py`):
  - 거리 dr × 방위 dθ 격자를 쓴다. 거리 범위는 1–100 km이고, 마지막 거리 칸은 남은 길이만큼이다.
  - scan마다 "확정 항적과의 연관 확률 합이 0.5 미만인 탐지점"을 칸별로 센다(c). 제외 규칙은 JIPDA-est와 같다.
  - 지수 망각: C ← a·C + c, N ← a·N + 1, a = exp(−1/τ).
  - 칸 밀도 = max(C / (N·칸 부피), 바닥값). 칸 부피의 단위는 m·rad이다.
  - **바닥값**은 JIPDA-est와 같은 밀도인 1 / (10 × 10 km × 22.5°) = 2.546e-5 /(m·rad)/scan으로 고정한다. 해석은 6절에 적었다.
  - 첫 scan 전에는 칸마다 탐지 1개로 둔다. JIPDA-est와 같다. 실제로는 첫 scan에 항적이 없으므로 쓰이지 않는다.
- 후보 8개, 이름은 c{dr km}_{dθ}_{τ}:

| 이름 | dr | dθ | τ (scan) |
|---|---:|---:|---:|
| c1_1.5_30 | 1 km | 1.5° | 30 |
| c1_1.5_100 | 1 km | 1.5° | 100 |
| c1_3_30 | 1 km | 3° | 30 |
| c1_3_100 | 1 km | 3° | 100 |
| c2_1.5_30 | 2 km | 1.5° | 30 |
| c2_1.5_100 | 2 km | 1.5° | 100 |
| c2_3_30 | 2 km | 3° | 30 |
| c2_3_100 | 2 km | 3° | 100 |

### 5.3 판정 (lam1000_map 기준, 수치 규칙)

**개선**: 아래 넷을 모두 만족할 때.
1. JIPDA-map의 lam1000_map 가짜 항적이 scan당 평균 8 이하.
2. lam1000_map GOSPA가 JIPDA-est보다 낮고, 짝 차이(JIPDA-map − JIPDA-est)의 95% 구간 상한이 0보다 작음.
3. lam5_map과 lam5_uniform 각각에서 JIPDA-map의 가짜 항적/scan 평균이 JIPDA의 1.10배 이하.
4. 같은 두 조건에서 ID switch 평균이 JIPDA의 1.10배 이하.

**부분 개선**: 2는 만족하지만 1, 3, 4 중 하나라도 어긋날 때. 어긋난 항목을 적는다.

## 6. 해석 (지시가 모호했던 곳)

- **바닥값**: "바닥값은 JIPDA-est와 같다"를 같은 밀도 값으로 읽었다. "칸마다 10 scan에 1개"를 그대로 작은 칸에 적용하면 1 km × 1.5° 칸에서 바닥 밀도가 150배가 되어, λ 1000 고른 클러터의 참 밀도(1.61e-3)보다도 높아진다. 그러면 추정 지도가 아니라 바닥값이 결과를 정한다. 그래서 JIPDA-est의 바닥 밀도 2.546e-5를 그대로 쓴다.
- **판정 기준**: 지시에 예로 든 기준을 그대로 채택했다. "10% 넘게 나빠지지 않음"은 seed 평균의 비율(JIPDA-map / JIPDA) ≤ 1.10으로 정했다.
- **비교 대상이 없는 조건**: 3단계 JIPDA-est가 없는 세 조건은 새로 돌려 보여 주기만 하고 판정에는 쓰지 않는다.
- **실행 시간**: 다른 세션(ASTRA 학습)과 CPU를 나눠 쓰므로, 3단계 실행 시간과 직접 비교하면 안 된다. 같은 밤에 돌린 JIPDA-map과 새 JIPDA-est끼리만 비교한다.
- **"자료로 추정"**: 추정기에는 참 밀도, 클러터 지도 모형, 고정 구역 위치를 전혀 주지 않는다. 탐지점만 쓴다.

## 9. 우선순위 2: 원뿔 안을 아는 항적 유지 (2026-11-22 22:05 KST 작성, 실행 전)

지시상 이 작업은 1순위 보고서를 03:30 KST 전에 push했을 때만 실행한다. 코드와 이 절은 1순위 평가가 도는 동안 미리 써 둔다. 실행은 그 조건을 확인한 뒤에 시작한다.

### 9.1 배경과 실행 가능 여부

- 3단계 사후 분석(`results/stage3/diag_near/summary.md`, M4, seed 20개)에서 원뿔을 켰을 때와 껐을 때(고각 상한 90°)의 ID switch 짝 차이: 스히폴 EKF +6.10 [+5.24, +6.96], IMM +6.60. KATL EKF +19.30 [+17.55, +21.05], IMM +18.90.
- 추적기가 지금 받는 것은 탐지점의 (거리, 방위, 시각)뿐이다. 하지만 센서 모형(M2–M4)은 표적 보고마다 Mode C 고도(100 ft 단위)로 경사 거리를 지상 거리로 고치고 있다. 즉, 모의 레이더는 표적 보고마다 Mode C를 이미 갖고 있다. 이 값을 탐지점에 붙여 추적기에 넘기는 것은 센서 모형이 가정하는 정보를 그대로 쓰는 것이므로 실행한다.
  - 허위 탐지(1차 레이더 클러터)에는 Mode C가 없다(NaN).
  - 이 때문에 "고도가 붙은 탐지점은 진짜 표적"이라는 정보가 생긴다. 이 정보는 원뿔 판단에만 쓰고 연관과 항적 관리에는 쓰지 않는다. 그래도 고도를 받은 항적만 유지 대상이 되므로, 고도가 없는 가짜 항적은 유지되지 않는다. 이는 SSR과 연계된 실제 항적이 고도를 갖는 것과 같은 구조다.
  - 고도 오차(Mode C 보고 오류, 기압 보정)는 넣지 않는다.

### 9.2 방법 (`src/radar_track_lab/cone.py`)

- 항적 고도는 마지막으로 연관된 보고의 Mode C 고도다.
- scan마다 확정 항적 중 고도를 아는 것에 대해 예측 조사 시각의 예측 위치를 구한다(고정점 2회, JPDA와 같은 방식). 지상 거리와 고도로 고각을 계산해(4/3 지구, 센서 모형과 같은 함수) 42°보다 크면 원뿔 안으로 본다.
- 원뿔 안 항적은 "유지"한다. 연관에 참여하지 않고, M-of-N 계수(hits, scans, misses)를 그대로 둔다. 상태는 갱신하지 않으므로, 다음에 연관될 때 마지막 갱신 시각부터 예측된다.
- 최대 유지 시간: T_max = 2·r_c / max(|v|, 50 m/s) + 9.6 s, 여기서 r_c = (고도 − 안테나 높이) / tan 42°.
  - 원뿔 지름을 항적 속도로 지나는 시간에 두 회전(9.6 s)을 더한 값이다.
  - 마지막 갱신에서 T_max가 지나면 유지를 끝내고 보통 규칙(연속 5회 누락이면 삭제)으로 돌아간다.
- 그 밖의 것(필터, 게이트, 배정, 확정·삭제 규칙, IMM 매개변수)은 3단계 동결값 그대로다.
- 실행 경로: `scripts/stage4_cone_run.py`가 자기 프로세스 안에서만 `sim.simulate_scans`와 `sim.make_tracker`를 감싼다. 감싼 `simulate_scans`는 Mode C를 붙이고, 감싼 `make_tracker`는 `ekf_cone`, `imm_cone`을 만든다. 1순위 평가가 도는 동안 `sim.py`를 바꾸지 않으려는 것이다. Mode C를 붙여도 난수 소비는 바뀌지 않는다.
- 퇴행 확인: 같은 스크립트로 유지를 끈 `ekf`, `imm`을 seed 2개 돌린다. ID switch, misses 잃음, 15 km 안 misses 잃음이 `results/stage3/diag_near`의 M4 값과 같아야 한다.

### 9.3 단위 시험 (`tests/test_stage4_cone.py`)

T_max 식, Mode C가 표적 보고에만 100 ft 단위로 붙는지, 레이더 위를 지나는 합성 직선 비행을 확인한다. 이 비행에서 원뿔 구간은 연속 누락 규칙(5회)보다 길다. 보통 EKF는 항적을 잃고 새 항적을 만들어야 하고(확정 ID 2개), 유지 EKF는 한 항적으로 이어 가야 한다(ID 1개). T_max가 음수이면 유지가 일어나지 않아야 한다.

### 9.4 실행과 지표

- M4, EHAM_1106_eval과 KATL_1106_peak, `ekf_cone`과 `imm_cone`, seed 20261106–20261125(20개). 3단계 diag_near와 같은 seed와 같은 모형이므로, 유지 실행의 탐지점은 3단계 M4 실행과 같다.
- 지표: ID switch, misses 잃음, 15 km 안 misses 잃음(3단계 `diagnose.classify_switches`), 가짜 항적/scan, GOSPA, RMSE, 유지된 항적-scan 수, 유지 시간 초과 수.
- **회복률** = (ID switch[M4] − ID switch[M4+유지]) / (ID switch[M4] − ID switch[M4, 원뿔 끔]). seed 평균으로 계산한다. 95% 구간은 seed 묶음 bootstrap(10,000회, 난수 seed 0)으로 낸다. M4와 유지는 seed별 짝이고, 원뿔 끔은 3단계 파일을 쓴다.
- 판정은 따로 두지 않는다(지시에 판정 기준이 없음). 대신 부작용으로 가짜 항적/scan, GOSPA, RMSE가 M4보다 10% 넘게 나빠지는지 적는다.
